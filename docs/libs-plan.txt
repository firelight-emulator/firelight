╌ Modularize Firelight Services into libs/

 Context

 firelight_lib is currently a monolith: ~80 .cpp files in a single add_library() call, with
 src/app fully public on the include path. Two services are already partially extracted
 (firelight_achievements, firelight_activity) but activity has build bugs and both have scope
 issues.

 The goal is to give each service its own libs/firelight/<service>/ module with:
 - include/firelight/<service>/ — public API only (interfaces + value types)
 - src/ — private implementation (concrete classes, SQLite repos, etc.)
 - Own CMakeLists.txt creating a STATIC library with proper PRIVATE/INTERFACE include scopes

 GUI models (QAbstractListModel subclasses) stay in src/gui/ — they're Qt bridge code, not
 domain logic.

 firelight_lib becomes a thin glue target: QML proxies, list models, event handlers, and
 main.cpp wiring.

 ---
 Conventions to Enforce Across All Modules

 - Abstract interfaces in include/ (e.g., IActivityLog, ISettingsRepository)
 - Concrete implementations in src/ (e.g., SqliteSettingsRepository)
 - Value types / structs in include/ (e.g., PlaySession, Savefile)
 - No third-party types (SQLite, SDL, discordpp types) in any public header
 - No ManagerAccessor usage inside module implementations — dependencies injected via
 constructors

 ---
 Root CMakeLists.txt Changes (Applied Incrementally)

 Per phase:
 1. add_subdirectory(libs/firelight/<module>)
 2. Remove migrated .cpp files from firelight_lib source list
 3. Add target_link_libraries(firelight_lib ... firelight_<module>)

 After all phases:
 - Change target_include_directories(firelight_lib PUBLIC ... ${CMAKE_SOURCE_DIR}/src/app) →
 PRIVATE
 - firelight_lib shrinks to: QML proxies, list models, event handlers, manager_accessor.cpp,
 service_accessor.cpp

 ---
 ManagerAccessor / ServiceAccessor Cleanup

 As each service migrates away from ManagerAccessor::get*() calls in their implementation,
 remove that service's getter from ManagerAccessor. By Phase 9, these classes should only be
 used in main.cpp (for wiring) and src/gui/ (for QML proxies that still bridge to services).
 Eventually they can be deleted entirely once QML proxies also take their deps via constructor.

 ---
 Verification

 After each phase:
 1. cmake -B build -G "MinGW Makefiles" — confirm clean configuration
 2. cmake --build build — confirm no link errors
 3. cd build && ctest --output-on-failure — confirm all tests still pass
 4. Run the app and exercise the affected feature

 After all phases:
 - Confirm src/app include path is no longer PUBLIC in firelight_lib
 - Confirm no module's include/ contains implementation headers or third-party types
 - Confirm ManagerAccessor and ServiceAccessor are used only in src/gui/ and main.cpp
